## 초록

피싱 이메일 탐지는 본문 문맥, 발신자 인증, URL 및 도메인 관계, HTML 구조, 첨부파일 검사처럼 성격이 다른 증거를 함께 다뤄야 한다. 기존의 단순 점수 합산은 엔진의 가용성, 증거 간 충돌, 증거 부족을 하나의 위험 점수에 섞어 표현하기 때문에 판정 근거와 실패 원인을 구분하기 어렵다. 본 연구는 여러 분석 엔진의 출력을 공통 특징으로 변환하고, 불확실성을 보존하는 증거 결합과 학습 기반 메타 분류를 병렬로 비교하는 피싱 이메일 분석 프레임워크를 제안한다. 합성 이메일 10,000건을 15개 시나리오 그룹으로 나누고, 외부 10중·내부 5중의 중첩 그룹 교차검증을 적용하여 시나리오 중복과 상위 문맥 모델의 학습 누수를 통제하였다. 문맥 모델 단독은 정확도 98.85%, 재현율 97.88%, 오탐률 0.18%를 기록했다. Logistic Regression 결합은 정확도 99.03%, 재현율 98.26%, 오탐률 0.20%를 기록하여 미탐을 106건에서 87건으로 줄였다. 짝지은 오류에 대한 정확 McNemar 검정은 p=0.000912였으며, 시나리오 그룹 부트스트랩으로 추정한 정확도 차이의 95% 신뢰구간은 0.011%p~0.427%p였다. 그러나 학습에 사용하지 않은 실제 이메일 8건에서 결합 모델은 6건만 정확히 분류하여 합성 데이터의 개선이 실제 소표본에서 재현되지 않았다. 제거 및 장애 실험에서도 결합 모델이 문맥 엔진에 크게 의존하는 것으로 나타났다. 결과는 결합 계층이 합성 시나리오에서 미탐을 줄일 수 있음을 보이는 동시에, 실제 배치 전 엔진별 증거 다양성과 외부 평가가 필요함을 보여준다.

**주제어:** 피싱 이메일, 증거 결합, 불확실성, 중첩 그룹 교차검증, 다중 엔진 분석, 메타 분류

## 1. 서론

피싱 이메일은 정상적인 업무 안내, 계정 보안 알림, 결제 요청 및 기관 공지를 모방하며 수신자의 행동을 유도한다. 공격자는 본문 표현뿐 아니라 발신 도메인, 표시 URL, HTML 구성, 첨부파일 및 메일 인증 상태를 조합하므로 단일 특징이나 단일 분류기만으로 모든 공격 유형을 포괄하기 어렵다 `[피싱 공격 및 탐지 분류 연구 인용 필요]`.

실제 분석 시스템은 서로 다른 실패 양상을 가진 여러 엔진을 사용한다. 본문 문맥 모델은 의미적으로 자연스러운 공격을 탐지할 수 있지만 정상 보안 안내를 피싱으로 오인할 수 있다. URL 및 도메인 분석은 객관적인 관계를 제공하지만 공식 도메인이 탈취되거나 공격 URL이 포함되지 않은 경우 한계가 있다. SPF, DKIM, DMARC와 같은 인증 정보는 발신 경로를 검토하는 데 유용하지만 인증 성공 자체가 본문의 안전성을 보장하지 않는다. 첨부파일 백신 검사와 정적 구조 검사는 악성 파일을 탐지할 수 있으나 탐지 데이터베이스와 실행 환경에 의존한다 `[이메일 인증·URL·첨부파일 탐지 연구 인용 필요]`.

이러한 이질적인 출력을 결합할 때 단순 가중합은 세 가지 문제를 만든다. 첫째, 엔진 미실행과 안전 판정을 같은 낮은 점수로 취급할 수 있다. 둘째, 서로 충돌하는 증거를 상쇄해 실제 불확실성을 숨길 수 있다. 셋째, 같은 템플릿이나 시나리오가 학습·시험 집합에 함께 들어가면 결합 모델의 성능이 과대평가될 수 있다. 본 연구는 이 문제를 해결하기 위해 증거 부족과 충돌을 명시적으로 기록하고, 시나리오 그룹을 완전히 분리한 중첩 검증 절차를 적용한다.

본 연구의 질문은 다음과 같다.

- **RQ1:** 문맥 ML과 구조 증거를 결합하면 문맥 ML 단독보다 피싱 탐지 성능이 개선되는가?
- **RQ2:** 각 증거군을 제거했을 때 성능은 어떻게 변하며 어떤 엔진에 가장 크게 의존하는가?
- **RQ3:** 엔진 미실행 또는 문맥·구조 충돌 상황에서 결합 계층은 어떤 실패 양상을 보이는가?
- **RQ4:** 합성 데이터에서 관측된 개선이 학습에 사용하지 않은 실제 이메일 사례에서도 재현되는가?

본 연구의 기여는 다음과 같다.

1. 본문 문맥, 인증, URL·도메인, HTML, 첨부파일 및 외부 카탈로그 결과를 공통 증거 표현으로 연결했다.
2. 피싱 지지, 정상 지지, 미해결 불확실성을 분리하고 충돌 질량을 불확실성으로 이동시키는 결합 방식을 구현했다.
3. 상위 문맥 모델의 out-of-fold 예측만 메타 분류기에 전달하는 중첩 그룹 교차검증 절차를 구축했다.
4. 제거 실험, 엔진 장애, 자연 발생 충돌, 실제 이메일 사례 감사를 통해 결합 성능의 원인과 한계를 함께 분석했다.

## 3. 제안 프레임워크

### 3.1 전체 처리 구조

프레임워크는 EML 파일을 입력으로 받아 다음 증거를 생성한다.

1. 헤더 체인과 발신자 인증 관측
2. 제목·본문의 다국어 문맥 위험도
3. URL 구조와 표시 주소·목적지 관계
4. 수집된 목적지 HTML의 정적 구조
5. 주장 기관과 공식 사이트·도메인의 관계
6. 첨부파일 정적 검사와 사용 가능한 백신 결과
7. Razor 카탈로그 조회 결과

각 엔진의 원시 출력은 판정 반영 신호, 연속 점수, 실행 가능 여부, 실패 수 및 구조 개수 특징으로 변환된다. 모델 입력에는 최종 판정이나 정답 라벨에서 파생된 값을 포함하지 않는다.

### 3.2 특징 표현

결합 벡터는 판정 신호 이진값과 연속·개수 특징으로 구성된다. 주요 특징은 문맥 점수와 가용성, HTML 쌍 점수와 가용성, 규칙 진단값, 인증 실패 수, 첨부파일 위협·경고·실패 수, 표시 주소 불일치 수, 공식 기관 주장 불일치 수, 페이지 수집 성공 수, HTML 구조 신호 수 및 미실행 엔진 수다.

문맥 모델은 제목과 본문에서 정규화된 문장 표현을 계산하고 피싱 확률을 출력한다. 다국어 입력은 언어 감지와 로컬 번역 경로를 거쳐 한국어 중심 학습 표현에 맞춘다. 번역 실패와 모델 미설치는 낮은 위험 점수가 아니라 엔진 미가용 상태로 기록한다.

### 3.3 불확실성 보존 결합

각 증거원 (i)는 피싱 지지 (m_i(P)), 정상 지지 (m_i(B)), 불확실성 (m_i(U))을 가지며 다음 조건을 만족한다.

\[
m_i(P)+m_i(B)+m_i(U)=1.
\]

신뢰도 (r_i\in[0,1])를 적용한 뒤 지지 질량은 다음과 같이 할인한다.

\[
m'_i(P)=r_i m_i(P),\quad m'_i(B)=r_i m_i(B),
\]

\[
m'_i(U)=1-m'_i(P)-m'_i(B).
\]

둘 이상의 증거가 충돌할 때 피싱과 정상의 교차 질량을 어느 한쪽으로 정규화하지 않고 불확실성으로 이동시킨다. 모든 증거의 비정규 결합을 완료한 뒤 빈 집합의 총 충돌 질량을 (U)에 한 번 더한다. 이에 따라 엔진 실행 순서가 결과에 영향을 주지 않으며, 엔진 미실행은 피싱 또는 정상을 지지하지 않는 완전 불확실성으로 표현된다.

이 결합은 설명과 불확실성 기록을 위한 실험 경로이며 운영 GUI 판정을 직접 변경하지 않는다. 별도의 학습 결합기는 동일 특징 벡터를 Logistic Regression 및 Random Forest에 입력하여 비교한다.

## 4. 실험 방법

### 4.1 데이터

주 실험에는 정상 5,000건과 피싱 5,000건으로 구성된 합성 이메일 10,000건을 사용했다. 데이터는 15개 시나리오 그룹을 포함하며 모든 주소와 URL은 예약 도메인을 사용한다. 첨부파일은 무해한 자리표시자다. 따라서 본 데이터로 첨부파일 악성코드 탐지의 실제 성능을 평가할 수 없다.

별도 사례 감사에는 사용자가 웹메일에서 내려받은 실제 EML 8건을 사용했다. 정답은 정상 5건과 피싱 3건이다. 이 8건은 모델 학습, 특징 선택, 규제값 선택 및 임계값 결정에 사용하지 않았다.

### 4.2 누수 통제 평가

외부 평가에는 10중 Stratified Group K-fold를 사용해 같은 시나리오의 이메일이 외부 학습·시험 집합에 동시에 포함되지 않도록 했다. 각 외부 학습 집합 안에서는 최대 5개의 내부 그룹 폴드를 사용해 문맥 Logistic Regression의 규제값 (C)를 선택했다.

메타 결합기의 외부 학습 입력에는 내부 폴드에서 얻은 out-of-fold 문맥 확률만 사용했다. 외부 시험 입력에는 해당 외부 시험 집합을 보지 않은 문맥 모델의 확률을 사용했다. 이 절차는 문맥 모델의 학습 내 예측이 메타 결합기의 성능을 부풀리는 것을 방지한다.

### 4.3 비교 방법과 지표

다음 방법을 비교했다.

- 문맥 ML 단독
- 구조 특징만 사용한 Logistic Regression
- 문맥과 구조 특징을 결합한 Logistic Regression
- 문맥과 구조 특징을 결합한 Random Forest

지표는 AUC, 정확도, 오탐률, 재현율, TN, FP, FN, TP다. 동일한 외부 시험 표본에서 발생한 오류 차이는 정확 McNemar 검정으로 분석했다. 시나리오별 상관을 고려하기 위해 15개 시나리오 그룹을 재표집하는 5,000회 그룹 부트스트랩으로 정확도 차이의 95% 신뢰구간을 계산했다.

### 4.4 제거·장애·충돌 실험

문맥, 인증, URL·도메인, 첨부파일, HTML·페이지, 기존 규칙 특징을 각각 제거하고 Logistic 결합을 다시 학습했다. 엔진 장애 실험에서는 외부 시험 시점에 문맥 특징 전체 또는 구조 특징 전체를 제거했다. 충돌 실험은 문맥 단독과 구조 단독의 이진 판정이 다른 외부 시험 표본만 추출해 각 방법을 비교했다.

## 5. 결과

### 5.1 전체 성능

| 방법 | AUC | 정확도 | 오탐률 | 재현율 | FP | FN |
|---|---:|---:|---:|---:|---:|---:|
| 문맥 ML 단독 | 0.998872 | 0.9885 | 0.0018 | 0.9788 | 9 | 106 |
| 구조 Logistic | 0.803559 | 0.8248 | 0.0404 | 0.6900 | 202 | 1550 |
| 문맥+구조 Logistic | 0.998528 | 0.9903 | 0.0020 | 0.9826 | 10 | 87 |
| 문맥+구조 Random Forest | 0.998008 | 0.9918 | 0.0058 | 0.9894 | 29 | 53 |

Logistic 결합은 문맥 단독보다 정확도가 0.18%p 높았으며 미탐을 19건 줄였다. 오탐은 1건 증가했다. Random Forest는 미탐을 53건까지 줄였지만 오탐이 29건으로 증가했다. AUC는 두 결합 모델 모두 문맥 단독보다 낮았다. 따라서 임계값 0.5에서 정확도와 재현율은 개선됐지만 전체 순위 품질이 향상됐다고 해석할 수는 없다.

### 5.2 통계 검정

Logistic 결합만 정확했던 표본은 23건, 문맥 단독만 정확했던 표본은 5건이었다. 정확 McNemar 검정의 p 값은 0.000912였다. 시나리오 그룹 부트스트랩에서 정확도 차이의 95% 신뢰구간은 0.011%p~0.427%p였다. 이 결과는 합성 시나리오 모집단 안에서 Logistic 결합의 개선이 작지만 일관됨을 보여준다.

Random Forest의 정확도 차이는 +0.33%p였고 McNemar 검정은 유의했지만, 그룹 부트스트랩 95% 신뢰구간은 -0.377%p~+1.298%p로 0을 포함했다. 따라서 Random Forest의 개선은 특정 시나리오 구성에 민감할 가능성이 있다.

### 5.3 제거 실험

| 제거 조건 | 정확도 | 오탐률 | 재현율 |
|---|---:|---:|---:|
| 문맥 제거 | 0.8248 | 0.0404 | 0.6900 |
| 인증 제거 | 0.9888 | 0.0020 | 0.9796 |
| URL·도메인 제거 | 0.9903 | 0.0020 | 0.9826 |
| 첨부파일 제거 | 0.9903 | 0.0020 | 0.9826 |
| HTML·페이지 제거 | 0.9903 | 0.0020 | 0.9826 |
| 기존 규칙 제거 | 0.9903 | 0.0020 | 0.9826 |

문맥 특징을 제거했을 때 성능이 가장 크게 하락했다. 인증 특징 제거도 미탐을 87건에서 102건으로 증가시켰다. URL·도메인 제거는 임계값 기반 지표를 바꾸지 않았지만 AUC를 0.998528에서 0.997756으로 낮췄다. 첨부파일과 HTML 특징 제거가 결과를 바꾸지 않은 이유는 해당 엔진이 본질적으로 무용하기 때문이 아니라 합성 데이터에 악성 첨부파일과 실제 수집 HTML 변이가 없기 때문이다.

### 5.4 장애 및 충돌

문맥 엔진을 시험 시점에 제거하면 결합 모델은 모든 피싱을 정상으로 분류하여 재현율이 0이 됐다. 구조 엔진을 제거하고 문맥만 남겼을 때 정확도는 98.77%, 재현율은 97.72%였다. 이는 현재 결합 계층이 문맥 엔진에 과도하게 의존하며 문맥 장애에 견고하지 않음을 보여준다.

문맥 모델과 구조 모델이 충돌한 표본은 1,831건이었다. 이 부분집합에서 문맥 단독 정확도는 94.70%, Logistic 결합은 95.85%였다. 결합은 충돌 표본에서 일부 오류를 교정했지만 구조 단독 정확도는 5.30%에 불과했다. 이는 구조 특징이 독립적인 주 분류기라기보다 특정 오류를 보정하는 보조 증거로 작동했음을 의미한다.

### 5.5 실제 이메일 사례 감사

실제 이메일 8건에서 운영 정책과 학습 결합은 각각 6건을 정확히 분류했다. 두 방식의 총 정확도는 같았지만 오류 구성은 달랐다. 운영 정책은 5번 정상 메일을 오탐하고 6번 피싱을 미탐했다. 학습 결합은 5번을 정상으로 교정했지만 7번 정상 메일을 오탐했고 6번 피싱은 계속 놓쳤다.

6번은 문맥 점수가 0.000076이고 반영 가능한 구조 신호도 없어 모든 주요 입력이 동시에 실패했다. 7번은 정상 메일이지만 문맥 점수가 0.997976이었고 학습 결합도 0.857526을 출력했다. 운영 정책은 객관 구조 증거가 없어 문맥 양성을 참고 신호로만 유지함으로써 오탐을 피했다. 8번 피싱은 문맥 점수 0.997672와 유사 사칭 도메인 신호가 함께 관측되어 두 방식 모두 탐지했다.

## 6. 논의

### 6.1 연구 질문에 대한 답

**RQ1:** 합성 데이터에서는 Logistic 결합이 문맥 단독보다 정확도와 재현율을 소폭 개선했다. 다만 AUC는 낮아졌고 실제 8건에서는 총 정확도가 개선되지 않았다.

**RQ2:** 문맥 신호가 성능 대부분을 설명하며 인증 특징이 추가적인 기여를 보였다. URL·도메인 특징은 순위 품질에 작은 기여를 했고, 첨부파일과 HTML 기여는 현재 데이터로 평가할 수 없었다.

**RQ3:** 문맥 엔진 장애 시 결합 모델이 사실상 작동하지 않았다. 자연 충돌 표본에서는 결합이 문맥 단독보다 나았지만, 문맥의 강한 실제 오탐을 항상 억제하지는 못했다.

**RQ4:** 실제 8건에서는 합성 데이터의 성능 개선이 재현되지 않았다. 이 표본은 통계적 일반화를 위한 규모가 아니지만 운영 승격을 보류할 충분한 실패 사례를 제공했다.

### 6.2 운영 판정과 연구 모델의 분리

학습 결합 모델은 실험 결과에만 기록하고 GUI의 기존 판정을 변경하지 않았다. 이는 실제 감사에서 학습 결합이 7번을 오탐했고 6번을 미탐했기 때문이다. 현재 운영 정책처럼 문맥 단독 양성을 객관 증거와 분리해 표시하는 방식은 일부 실제 오탐에 대한 안전장치로 작동했다.

### 6.3 SCI 수준 기여의 범위

본 연구가 주장할 수 있는 기여는 모든 환경에서 우월한 피싱 탐지기가 아니다. 핵심은 다음 세 요소의 결합이다. 첫째, 서로 다른 엔진의 가용성과 실패를 명시적으로 기록한다. 둘째, 충돌을 인위적인 확신으로 바꾸지 않고 불확실성으로 보존한다. 셋째, 스태킹 과정에서 상위 모델의 학습 내 예측 누수를 차단하는 그룹 중첩 검증을 제공한다. 실제 데이터 확장이 어렵더라도 이 평가 설계와 실패 분석은 재현 가능한 방법론적 기여가 될 수 있다.

## 7. 타당성 위협과 한계

### 7.1 구성 타당성

합성 데이터의 정상·피싱 라벨은 생성 규칙에 의해 결정됐다. 실제 사용자의 의도, 조직별 업무 맥락 및 공격 성공 가능성을 완전히 반영하지 못한다. 모든 URL이 예약 도메인이며 첨부파일도 자리표시자이므로 실시간 웹 구조와 악성 파일 탐지 성능을 측정할 수 없다.

### 7.2 내부 타당성

시나리오 그룹 분리와 중첩 검증으로 직접적인 템플릿 누수를 줄였지만, 여러 시나리오가 공통 생성 문체나 생성 도구의 흔적을 공유할 수 있다. 그룹 수가 15개뿐이어서 일부 외부 폴드에는 하나의 시나리오만 포함됐다. Random Forest의 그룹 부트스트랩 구간이 넓은 것도 이 제약과 일치한다.

### 7.3 외부 타당성

실제 이메일은 8건뿐이며 특정 사용자와 수신 환경에 한정된다. 실제 정확도, 기관별 성능, 언어별 성능 또는 시간에 따른 성능 저하를 추정할 수 없다. 번역 기반 다국어 처리도 별도 언어별 정답 집합으로 검증되지 않았다.

### 7.4 결론 타당성

10,000건의 행 단위 표본은 많지만 실질적인 독립 단위는 15개 시나리오 그룹이다. McNemar 검정은 행 단위 짝지은 오류를 사용하므로 그룹 상관의 영향을 받을 수 있다. 이를 보완하기 위해 그룹 부트스트랩을 함께 보고했으나 그룹 수가 적어 신뢰구간 자체도 불안정할 수 있다.

### 7.5 시스템 한계

문맥 엔진이 실행되지 않으면 현재 Logistic 결합은 모든 피싱을 놓치는 장애 양상을 보였다. 엔진 미가용 상태를 학습 데이터에 충분히 포함하지 않았기 때문이다. Razor와 백신 결과는 외부 데이터베이스와 로컬 환경에 의존한다. 공식 사이트 검색과 페이지 수집은 네트워크 상태 및 사이트 변경의 영향을 받는다.

## 8. 결론

본 연구는 피싱 이메일 분석에서 문맥, 인증, URL·도메인, HTML 및 첨부파일 증거를 결합하고 불확실성과 엔진 가용성을 분리해 기록하는 프레임워크를 구현했다. 누수를 통제한 중첩 그룹 교차검증에서 Logistic 결합은 문맥 단독보다 미탐을 줄이고 정확도를 소폭 개선했다. 그러나 실제 이메일 감사와 엔진 장애 실험은 이 개선이 문맥 엔진에 크게 의존하며 실제 일반화가 확인되지 않았음을 보여줬다. 따라서 현재 결합 모델은 운영 판정기가 아니라 연구·비교용 계층으로 유지한다. 향후 연구는 실제 출처가 확인된 이메일 확대, 악성 첨부파일과 실제 HTML 쌍 평가, 언어별 외부 검증, 엔진 누락을 포함한 학습을 통해 결합 계층의 견고성을 평가해야 한다.
