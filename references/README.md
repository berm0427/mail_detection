# 참조 근거 등록부

registry.json은 프로젝트 관리자가 확인한 자료만 등록하는 로컬 설정입니다. 기본값은 빈 목록이며 시험용 가상 기관을 공식 기관으로 넣지 않습니다. 메일·검색 결과·DNS 응답으로 자동 갱신하지 않습니다. 파일 내용에 verified라고 쓰였다고 외부 진위를 자동 검증하는 기능이 생기는 것은 아닙니다. 등록 담당자가 출처를 검토해야 합니다.

도메인 항목 필수 필드:

```json
{
  "organization": "검토한 기관 이름",
  "domain": "기관이 소유하거나 사용하도록 확인된 호스트",
  "role": "official",
  "include_subdomains": false,
  "status": "verified",
  "source": "소유 또는 위탁 관계를 확인한 문서 URL/기록",
  "verified_at": "YYYY-MM-DD",
  "review_due": "YYYY-MM-DD"
}
```

role은 official, delegated_sender, delegated_link 중 하나. 도메인은 URL·경로가 없는 소문자 ASCII/IDNA 호스트로 입력합니다. 하위 도메인 포함은 명시적으로 true일 때만 허용합니다. 현재 날짜가 검토일과 재검토 기한 사이에 있어야 사용합니다. 등록되지 않은 도메인은 미확인이지 악성 확정이 아닙니다. 발신 주소는 위조 가능하므로 등록된 주소라고 인증 성공으로 취급하지 않습니다.

정상 메일 템플릿 항목:

```json
{
  "id": "고유 식별자",
  "organization": "도메인 항목과 같은 기관 이름",
  "kind": "email_html",
  "status": "verified",
  "source": "정상 발송을 확인한 근거",
  "verified_at": "YYYY-MM-DD",
  "review_due": "YYYY-MM-DD",
  "file": "templates/notice.html",
  "sha256": "검토한 UTF-8 HTML 파일의 SHA-256"
}
```

templates 폴더의 실제 정상 이메일 HTML을 참조합니다. 홈페이지·로그인 웹페이지를 이메일 템플릿으로 등록하지 않습니다. 웹페이지와 웹페이지 비교는 별도의 수집 근거·전용 평가가 필요하며 이 경로에서는 수행하지 않습니다. 등록부 폴더 밖 경로와 해시가 달라진 파일은 제외됩니다. 현재 비교는 태그 개수 구성의 유사도이며 시각적·의미적 진위 검사가 아닙니다. 공격자가 복사할 수 있어 유사도 1도 안전 증명이 아닙니다.

GUI를 재시작하고 분석하면 엔진별 근거에 기관·도메인 근거, 정상 이메일 템플릿, HTML ML이 표시됩니다. 미등록 상태에서 '비교 불가'는 정상 동작입니다. 실제 검토한 참조 자료를 확보해야 운영 비교가 가능합니다.

ML 도입 조건: 실제 이메일의 정상·피싱 라벨과 판정 근거, 출처·기관·캠페인/템플릿을 분리한 독립 평가셋, 규칙 대비 오탐/미탐 비교, 보정 및 판정 유보 기준이 필요합니다. 기존 본문 분류기와 문자/메신저 자료를 HTML 모델로 간주하지 않습니다. 현재 HTML ML은 미적용이며 임의 점수를 생성하지 않습니다.
